The History of Web Browsers

The history of the web browser started alongside the development of the World Wide Web. In 1989, Tim Berners-Lee developed the idea of the Web while working at CERN because there was a need for scientists and universities to share information more easily. By the end of 1990, he had created the first web server and the first browser, which was called WorldWideWeb.

The browser was originally developed on a NeXT computer and allowed users to access linked documents through what was then a completely new way of sharing information. CERN later made the World Wide Web software freely available in 1993, which was an important decision because it meant other organisations and developers could use and develop the technology without having to pay for it (CERN, n.d.).

Web browsers started becoming much more accessible during the early 1990s. One of the biggest developments was the release of Mosaic in 1993 by the National Center for Supercomputing Applications (NCSA).

Mosaic is considered one of the first popular graphical web browsers because it made the Web easier for ordinary computer users to understand and navigate. Instead of the Web mainly being something used by researchers and people with specialist technical knowledge, graphical browsers helped make it much more usable for the general public.

Mosaic became extremely popular and helped influence the development of Netscape Navigator, which was released in 1994 and quickly became one of the leading browsers of the time (NCSA, n.d.; Mozilla, n.d.).

As the Web became more popular, competition between browser companies increased. During the 1990s, Netscape Navigator and Microsoft's Internet Explorer competed heavily for users in what became known as the "browser wars".

Microsoft benefited from including Internet Explorer with Windows, and it eventually became the dominant browser. However, competition continued with the development of Mozilla and later Firefox, which provided users with another alternative and supported the idea of a more open Web.

Over time, browsers have continued to develop from fairly basic programs for displaying web pages into platforms that support video, applications, online shopping, cloud services and many of the activities people now complete every day. The development of browsers shows how the Web has moved from being designed mainly for information sharing between researchers to becoming an important part of everyday life (Mozilla, n.d.).

The three languages

HTML defines content and structure. CSS controls presentation and layout. JavaScript adds behaviour and interactivity. They are the three core front-end languages. Brendan Eich created JavaScript in 1995. Browsers contain a JavaScript engine, so visitors do not need a separate download.

document.body.classList.toggle("dark-mode"); // CSS defines the colours
Where JavaScript goes

JavaScript can sit between script tags in the head or body. Inline event attributes also exist, but this project uses an external script and event listeners to keep responsibilities separate. A shared external script is a toolbox that both pages can use. The defer attribute runs it after HTML parsing; button handlers run later, when clicked.

<!-- Recommended: in the head -->
<script src="script.js" defer></script>

<!-- Embedded script: head or body -->
<script>
    console.log("Hello from JavaScript");
</script>

<!-- Inline event example, not used in this project -->
<button onclick="alert('Hello')">Say hello</button>
Output and changing content

JavaScript can find an existing element and update its content. textContent changes plain text. innerHTML is a property, not a function; it parses HTML, so never insert untrusted user input through it. alert displays a message, console.log writes to developer tools, and window.print opens the print dialogue. document.write can replace the document after loading, so it is explained here but never executed.

document.getElementById("demo-output").textContent = "Hello!";
// Only use trusted markup with innerHTML:
document.getElementById("demo-output").innerHTML = "<strong>Hello!</strong>";
console.log("A message for the developer");
window.alert("Hello!");
window.print();
// Avoid: document.write("This could replace the page");
Statements, expressions and operators

A statement is an instruction. An expression produces a value. The equals sign assigns a value; it does not mean mathematical equality. Use === to compare without type conversion. Braces group statements into blocks.

let x, y, z;
x = 5;
y = 6;
z = x + y; // The expression x + y produces 11

if (z === 11) {
    console.log("The answer is " + z);
}
// Arithmetic: +  -  *  /  %  **
// Assignment: =  +=  -=
// Other literals: "John Doe", true, null
Variables, arrays and const

Think of a variable as a named chest that holds a value. Use const when the binding will not be reassigned, and let when it will change. const does not freeze an object or array. var is older and still valid, but prefer let and const in new code.

const firstName = "John"; // String
let score = 5;            // Number
score += 6;
const isLearning = true;  // Boolean
const browsers = ["Mosaic", "Firefox", "Chrome"];
browsers.push("Safari");  // Allowed: the array can change
// browsers = [];        // Not allowed: reassignment
Identifiers and readable comments

Names are case-sensitive. A simple identifier starts with a letter, underscore or dollar sign; later characters may include digits. Unicode letters are also supported. Reserved words such as let, var and class cannot be variable names. char is not reserved in JavaScript. Use descriptive camelCase names such as firstName, not firstname. Comments explain intent and are ignored during execution.

// A single-line comment
const browserCount = 6;

/* A multi-line comment explains
   a section of code. */

// console.log(browserCount); // Commented out: will not run
ES6 and block scope

let and const were introduced in ES6 (2015). Both are block-scoped: they belong to the surrounding pair of braces. var is function-scoped, or global when declared at the top of a classic script; an if block does not confine it. Keep variables in the smallest useful scope.

function demonstrateScope() {
    if (true) {
        let insideBlock = "Only available here";
        var insideFunction = "Available throughout this function";
    }
    console.log(insideFunction);
    // console.log(insideBlock); // Would cause a ReferenceError
}
